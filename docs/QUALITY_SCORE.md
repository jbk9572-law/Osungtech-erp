# 품질 점수와 올리는 방법

점수는 "영역별 지표"로 근거를 남긴다(`node scripts/quality-report.mjs`로 현재 숫자를 본다).
80점 미만 영역은 아래 방법으로 올리고, **다시 나빠지지 못하게 lint에 래칫(기준선 고정)으로 묻어둔다.**

| 영역 | 처음 | 지금(추정) | 80점 기준 | 올리는 방법 / 자동 검사 |
|---|---|---|---|---|
| UI 일관성 | 62 | 약 75 | 직접 박은 style 선언(폭 제외) 감소 + 컨트롤 높이 3단계 | `erp-u-*` 공용 클래스·`--erp-*` 토큰으로 이동, `check-inline-style-budget`(같은 값 재사용 금지 + 총량 기준선) |
| 접근성 | 50 | 약 70 | 이름 없는 입력칸/기호 버튼 0, 모달 대화상자·포커스 | `check-a11y-basics`(기준선 0), 모달 `role=dialog`·포커스 이동/복귀 |
| 모바일 | 60 | 약 68 | 터치 영역 40px, 고정폭 점검 | 터치 기기 표 밖 컨트롤 최소 40px, 표는 가로 스크롤 유지(`check-editable-grid-mobile-width`) |
| 보안 | 68 | 약 78 | 모든 서버 액션에 호출자 확인, 입력 서버 검증, 서버 차단 | `check-action-auth`(액션 268개), 입력 검증 공용(`order-items-input`, 모조지), 모듈 끈 회사 서버 차단 |
| 금액·재고 | 70 | 약 78 | 삭제/수정 생애주기 DB 테스트, 세액 규칙 단일화 | `db-tests/fifo-lifecycle`, `calcVatForTaxType` 한 곳 |
| 코드 구조 | 78 | 약 80 | 800줄 초과 파일 감소 | `check-file-size`(큰 파일은 더 커질 수 없고, 줄이면 상한도 낮춤) |
| 유지보수성 | 75 | 약 80 | 모듈 경계, 규칙 문서화 | `check-module-boundary`, 개발헌법 |

## 다음 단계(점수를 더 올리려면)
- UI: 남은 직접 박은 값 중 색/테두리 토큰형은 클래스로 옮김. 11px/12px 글자 크기는 화면을 보며 토큰(11.5/12.5)에 합칠지 결정. 모달 하단 버튼줄 공용 클래스.
- 접근성: 모달 Tab 포커스 가두기, 색으로만 구분하는 상태 표시에 글자 보강.
- 보안: 나머지 액션 입력 검증을 `order-items-input`처럼 공용화, 로그인 시도 제한은 신뢰할 수 있는 IP 헤더 확인 후 정리.
- 금액·재고: 수정 흐름(update) DB 테스트 확대, 재고 수동 조정과 FIFO 연결 설계 결정.
- 코드 구조: 매출/매입 등록 폼(각 약 1,600줄)에서 가격 계산·임시 입력 상태를 훅으로 분리.

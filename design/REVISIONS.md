# 수정사항 기록 (REVISIONS)

사용자가 화면에서 발견한 어긋남·개선 의견을 **코딩 전에 먼저 기록**하는 목록이다. 상태: 대기(기록만) → 진행 → 완료. 항목마다 원인(코드로 추정한 것 포함)과 같은 구조가 몇 곳인지(전수조사)를 적는다.

## R-001 · 수량 칸 힌트 글자 제거 — 상태: 대기(사용자 결정 완료, 코딩 전)

- **제안(사용자, 2026-11-23)**: 수량 칸 안의 "수량 (엑셀식 계산 가능)" 안내 글자는 빼는 게 낫다. 칸이 좁아 글자가 잘리고 오히려 복잡하다. **기능을 빼자는 것이 아니다.**
- **현재 코드**: `src/components/quantity-with-box-input.tsx` 50행 — 수식 입력이 켜져 있으면 placeholder가 `수량 (엑셀식 계산 가능)`. 포장 기준이 있으면 `수량 (예: 12×1=12)`.
- **같은 구조(전수)**: `QuantityWithBoxInput`을 쓰는 화면 5곳(매출 전표, 매입 전표, 할일 품목, 재고 조정, 재고 실사) — 부품 한 곳을 고치면 모두 같이 바뀐다.
- **계획**
  1. placeholder는 `수량` 한 단어로 통일한다. **결정(사용자, 2026-11-23): 포장 기준 예시 문구 `(예: 12×1=12)`도 같은 이유로 뺀다.**
  2. 수식 입력 기능은 그대로 둔다. 안내는 칸에 포커스가 갔을 때만 보이는 툴팁/`title`(예: `12*3처럼 계산식을 입력할 수 있습니다`)로 옮긴다.
  3. 표 머리 `수량`의 `title`에도 같은 안내를 둔다.
- **주의**: 수식 칸임을 알려 주는 표시(예: 머리글 파란 글씨)가 이미 있다 — 그 표시는 유지.

## R-002 · 표 안 입력칸 모양 불일치 — 규격·단가만 둥근 테두리 — 상태: 대기(사용자 결정 완료, 코딩 전)

- **발견(사용자, 2026-11-23)**: 매출전표 입력 표에서 규격·단가 칸만 둥근 테두리 입력칸이고, 품목·관리번호·수량·금액은 테두리가 없다. "이게 맞나?"
- **판단: 맞지 않다(일관성 위반).** 같은 표 안의 입력칸은 한 가지 모양이어야 한다(디자인 규칙: 규격표 §7 블록 규칙, 엑셀식 표는 셀 입력 하나).
- **원인(코드로 추정)**: `src/components/new-sale-form.tsx` 1354행(규격)·1405행(단가)이 `className="erp-input w-full"`로 테두리 있는 일반 입력 클래스를 직접 지정하고, 품목·관리번호·수량 등은 클래스를 주지 않아 표 칸 기본 모양(테두리 없음)으로 나온다. 확인 못 함: 모든 칸의 최종 CSS를 화면에서 열어 보지는 않았다.
- **같은 구조(전수)**: `className="erp-input w-full"`가 컴포넌트 **30개 파일 92곳**. 이 중 표(`<td>`) 안에 있는 것이 전표·입력 표 대상이고, 정확한 개수는 작업 시작 때 다시 센다.
- **계획**
  1. 표 안 입력칸용 공용 클래스 하나(예: `erp-cell-input`)를 정한다 — 엑셀식: 평소엔 테두리 없음, 포커스 때 파란 테두리, 읽기 전용은 옅은 배경. 값은 규칙표 토큰만 사용.
  2. 표 안 `erp-input w-full` 호출부를 그 클래스로 바꾼다(자동 변환 + lint로 재발 방지: 표 안에서 `erp-input` 직접 사용 금지).
  3. 위 예외(넓은 전표 그리드 `wide-voucher-grid`)는 폭만 면제이고 이 모양 규칙은 지킨다.
- **결정(사용자, 2026-11-23): 추천대로.** 표 안 입력칸은 테두리 없음 + 포커스 때만 파란 테두리, 입력 가능한 칸은 옅은 바닥색으로 보완한다.

## R-003 · 매출 목록 도구 줄 정리 — 버튼 5개 → 표준 동작 + "일괄 작업 ▾" — 상태: 대기(사용자 결정 완료, 코딩 전)

- **발견(사용자, 2026-11-23)**: 도구 줄을 맨 위로 올렸더니 버튼이 `F2 신규 / 빠른등록(매출·수금·반품) / 엑셀 다운로드 / 홈택스 일괄발급 엑셀 / 세금계산서 일괄 작성` 5개가 한 줄에 늘어서 오히려 UI가 나빠졌다.
- **판단**: 표준 동작(조회·신규·수정·삭제·엑셀)을 맨 위 도구 줄에 두는 것은 맞다(시안과 같고 모든 목록에서 같은 위치). **이 화면 전용 동작까지 맨 위에 늘어놓는 것은 맞지 않다**(줄이 길어지고, 중요한 버튼이 묻히고, 표에서 멀다).
- **나빠 보이는 이유(사진 기준)**: ① 버튼 5개·긴 이름 ② 첫 버튼만 파랑+F2 표시, 나머지는 테두리 ③ 아이콘 색이 제각각(주황·파랑·회색) ④ 중요도 구분 없음.
- **결정(사용자): 추천대로.** 도구 줄 = `조회·신규·수정·삭제 | 엑셀 | 일괄 작업 ▾`. 빠른등록·홈택스 일괄발급 엑셀·세금계산서 일괄 작성은 "일괄 작업 ▾" 메뉴로 묶는다. 아이콘은 단색, 버튼은 한 가지 모양(28px).
- **같은 구조(전수)**: 매출·매입 목록(`PageToolbar`)이 같은 방식 — 작업 시작 때 전용 동작이 있는 화면을 다시 센다.
- **연관**: "F2 신규" 라벨은 "표 안 F2 = 셀 편집" 결정과 충돌한다 → 신규의 새 단축키를 정해 라벨을 바꾼다(작업 시 사용자에게 확인).
- **확인 필요**: 세 전용 동작 중 매일 쓰는 것이 있으면 단독 버튼으로 남긴다(사용자가 알려 주기로 함).
